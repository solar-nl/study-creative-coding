### Harfang 3D Architecture and Rendering Pipeline

- **New document** `notes/per-framework/harfang3d/architecture.md` (reviewer 4.0, blockers fixed afterwards) — the three static libraries and the generated skin, with the CMake link graph; the function-pointer `Reader`/`ReadProvider` abstraction behind every `FromFile`/`FromAssets` pair, and the asset system's last-added-wins folder order and whole-entry zip extraction; the scene as one `generational_vector_list` per component kind with 16-byte `(SceneRef, gen_ref)` handles that survive scene destruction; the create/destroy/`GarbageCollect` lifecycle and the memoized world-matrix recursion; systems (Lua VM, Bullet) as external objects synced in a fixed order; `PipelineResources` and the budgeted load queues; how `bind_harfang.py` features (`_inline`, `arg_out`, `arg_in_out`, a direct `bgfx::frame` binding) explain the C++ shapes, and the `fabgen.h` back-dependency. - **New document** `notes/per-framework/harfang3d/rendering-pipeline.md` (reviewer 3.86, blockers fixed afterwards) — bgfx view ids as tickets threaded by reference, verified against the bgfx sort-key encoding at the pinned nested commit; the nine-stage basic path with a worked frame (spot shadow ticket 0, cascades 1 to 4, opaque 5, transparent 6); eight light slots and the two shadow casters; the material-variant times pass-configuration shader scheme (2^N variants x 10 configurations, precompiled by assetc, loaded on demand by file name); the AAA chain of targets and passes; capture and backend init. ## 2026-10-25

### Open Formats Research

Research pass on open formats for 2D and 3D assets, outside the repo's usual lane of framework source, so the work products live in `research/open-formats/`.

- **New brief** `research/open-formats-research-brief.md` — the openness criterion (published spec, permissive license, stewarding body), domains in and out, capture fields, the three research strands, and the OpenUSD question (import only, interchange, or scene model)
- **New landscape** `research/open-formats/README.md` — open formats by stewarding body (ASWF, AOUSD, Khronos, W3C, ISO and de facto) and domain, with versions, dates and licenses fetched 2026-10-25. Findings: OpenEXR 3.5.2, MaterialX 1.39.5 with OpenPBR 1.1.1, OpenUSD 26.11.1 with the AOUSD Core Specification at 1.0.1 (1.1 announced, unpublished), glTF 2.1 announced but not in the registry, PNG Third Edition (2025) with APNG and HDR chunks, SVG 2 still a Candidate Recommendation, JPEG XL enabled by default in Chrome and Firefox in October 2026. Governance footnotes: Alembic was never an ASWF project, USD's spec text is CC-BY-ND, Rive's runtime is MIT but its format is vendor-owned, FBX fails every criterion
- **New survey** `research/open-formats/framework-support-matrix.md` — which of 20 studied projects import or export each format and through what mechanism, cited `path:line` at the current checkouts. Findings: three.js reads USD in pure JavaScript with a composition engine and maps OpenPBR; Babylon.js ships OpenUSD as WASM and has a native `OpenPBRMaterial` plus a `KHR_materials_openpbr` writer; Filament's gltfio reads ten material extensions; no native or Rust project has a verifiable USD reader; no project keeps a foreign scene model alive at runtime (all resolve glTF and USD into their own structures at load); tixl's `CombineBuffer` switch is the one hierarchy-or-flat choice exposed to users
- **New crate map** `research/open-formats/rust-crates.md` — the Rust crate per format with versions, licenses, downloads and `wasm32` status verified against the crates.io and GitHub APIs. Findings: `openusd` 0.8.0 (pure Rust, composition, tested against the AOUSD spec) appeared in 2026; `usvg`/`resvg` 0.49.0; `vello_svg` and `velato` target compute `vello` 0.10, not `vello_gpu`; `gltf` has had no release since 2024 and lacks flags for five material extensions; no Rust implementation of MaterialX, OpenColorIO, Alembic, NanoVDB or OpenTimelineIO
- **New insight** `insights/open-formats.md` and **ADR-006** in `insights/architecture-decisions.md` — the tiering table (import tier 1 and 2, export, ignore) with a crate and a one-sentence reason per format; OpenPBR as Flux's material vocabulary (the four OpenPBR-style glTF extensions Babylon ships are open Khronos pull requests, not ratified); the USD stance: interchange, flatten on import and export, keep the operator graph as source of truth, give nodes stable hierarchical paths so the scene-model stance stays open
- Registry updates: `insights/README.md`, `notes/themes/README.md`, `notes/themes/systems/asset-loading.md` (stub now points at the format survey)
